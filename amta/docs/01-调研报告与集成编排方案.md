# Automation Manga Translate Agent — 调研报告与集成编排方案

> 调研日期：2026-08-22（本机时间线）
> 调研范围：①ChatGPT 分享讨论 ②koharu 仓库（当前 main + 历史版本）③本地 koharu 安装（v0.59.1）④本地轮子 manga-localization
> 调研方式：4 个并行 subagent + 主代理直接核验源码/文档/本地文件

---

## 0. 一句话结论

**完全可行的方案不是「再造 koharu」，而是「把 koharu 当漫画 CV/翻译执行层，用 LLM Agent 编排它，并补上 Story Memory、Scene 级翻译、像素级擦字、可验证 QA + 自动修复循环」。** 本机恰好拥有实现该方案的黄金组合：**本地 koharu v0.59.1（headless + REST API + MCP，可完全程序化驱动）+ 已验证跑通 41 页的本地编排轮子 + DeepSeek Agent 作为导演/验收器。唯一需要先决策的是：**钉在旧版 headless（立即可用）还是迁移到新版桌面 Agent（功能新但自动化面大幅收窄）**。

## 1. ChatGPT 讨论要点（来源：share 链接，已完整解码 3 轮对话）

### 1.1 用户诉求与 4 大痛点
用户因 DeepSeek 有了视觉能力（配合 ModLens 视觉插件），想重启搁置的「漫画自动翻译 workflow」，核心诉求：**AI 自己跑完 workflow 后自行验收**（原话：「现在 deepseek 模型有了眼睛，我认为其就可以自己跑完一个 workflow 后自行进行验收而不是发呆了」）。

4 个痛点：
| # | 痛点 | 本质 |
|---|------|------|
| 1 | 框外字检测难（AI 常漏读框外文字） | Text Detection / Segmentation 问题，不是 OCR 问题 |
| 2 | OCR 精度不足（例：豊姫→星姬） | OCR 模型选型 + 后校验（候选+词典比对）问题 |
| 3 | 句子孤立、缺上下文（人物/剧情/语气） | 架构问题：Story Memory + Scene 级翻译 |
| 4 | 框外字擦除难（与头发/速度线/网点混层） | 像素级 Mask + 专用 Inpainting 问题 |

### 1.2 ChatGPT 给出的 10 层流水线
```
CV 检测 → 专用 OCR → Story Memory → Scene-level Translation → Segmentation Mask
→ 专用 Inpainting → Typesetting → Programmatic QA → Vision QA → 自动 Repair Loop
```
核心原则（引文）：
- 「不要把视觉能力理解成一个模型，而要理解成一个**视觉工具链**」；「DeepSeek 做导演、上下文理解、决策和验收；专用模型做检测、OCR、分割、修复」
- 「看懂图片 ≠ 恢复图片」→ Inpainting 必须按像素 mask 做
- 「不要让 AI 自己说'我做完了，看起来没问题'」→ **Objective QA（尤其 Text residue QA：译后重跑日文检测器查残留）+ Vision QA 双轨**
- **页面质量分级**（决定自动化程度）：Level A 普通对白页全自动；Level B 复杂背景页自动但重点检查；Level C 复杂 SFX 页由 DeepSeek 判断保留原文+注释（追求「页面自然、可读、无破坏」而非「100% 删日文」）
- 「不造 koharu，而是把 koharu 已有的能力包装成 DeepSeek 可调用的工具」
- 先做 4 个 benchmark（Detection 100 页 / OCR 500 crop / Inpainting 100 困难区域 / Translation consistency 10-20-30 页），用 10~20 页漫画验证四个痛点
- 与 koharu issue #864（2026-07）的方向一致：project-level JSON settings 保 terminology/persona 一致性

### 1.3 对本次调研的直接指引
本次调研的「核心三问」：①koharu 能否找全框外字 ②Manga OCR 能否准确读日语 ③Inpainting 对复杂背景够不够好；第 4 问（翻译上下文）是 Agent/Memory 架构问题，可自行解决。

## 4. 目标架构：Automation Manga Translate Agent（AMTA）

### 4.1 设计原则（来自 ChatGPT 讨论 + 本地实践）
1. **不造 koharu**：koharu = 漫画 CV/翻译执行层（检测/OCR/LLM 翻译/Inpainting/排版/导出），通过其 REST API / MCP 调用。
2. **LLM Agent 做导演**：规划（哪几页、哪个阶段）、决策（是否重翻/重擦）、验收（QA 判定 PASS/FAIL）、修复循环调度。
3. **视觉证据不依赖单一 VLM**：框外字/残留检查用专用检测器 + 像素 mask；VLM/ModLens 只做理解与复核。
4. **验收双轨**：Programmatic QA（数量匹配、溢出、日文残留重检）+ Vision QA（原图+译图+元数据交给视觉模型出结构化 issues）。
5. **上下文三件套**：Story Memory（角色/术语/风格持久 JSON）+ Scene 级翻译（同场景多页合并翻译再拆回）+ 前页上下文（本地轮子已验证有效）。

### 4.2 组件分层
```
┌────────────────────────────────────────────────────────────┐
│  Director Agent（DeepSeek，本 DSH 环境）                      │
│  规划 / 翻译决策 / QA 验收 / Repair Loop 调度 / 报告           │
└───────────────┬──────────────────────────────┬─────────────┘
                │ REST(4000) / MCP(/mcp)       │ 视觉复核
┌───────────────▼──────────────────────┐  ┌────▼─────────────┐
│ Orchestration Layer（编排层）          │  │ Vision QA        │
│ · koharu API 封装（搬自本地轮子）        │  │（ModLens/VLM 或  │
│ · Story Memory / glossary 管理        │  │ koharu view/渲染图│
│ · Scene 级翻译拆分                     │  │  + DeepSeek 判）  │
│ · 批量调度 + progress.json 断点续传     │  └──────────────────┘
│ · 程序化 QA（residue 检测等）           │
└───────────────┬──────────────────────┘
                │ HTTP /api/v1 + SSE /events
┌───────────────▼────────────────────────────────────────────┐
│ Koharu v0.59.1 headless（D:\我的汉化\workflow\bin\koharu.exe）│
│ Detection → OCR → LLM 翻译 → Inpainting → Typesetting → 导出  │
│ （可注入 systemPrompt：角色表/术语表/前页上下文/记忆）           │
└────────────────────────────────────────────────────────────┘
```

### 4.3 端到端流程（对齐 10 层流水线）
```
1. 准备：Story Memory（角色表/术语表/风格，复用 gensokyo_cast.json 格式）+ 页序
2. Import：POST /projects + /pages（批量）
3. Detect+OCR：POST /pipelines（steps=detect,ocr / pp-doclayout-v3,...manga-ocr），SSE 轮询
4. 框外字复核（痛点1）：对低置信/漏检区跑字体检测或二次检测；结果并入 scene
5. OCR 校正（痛点2）：候选+编辑距离比对角色词典 → 触发二次视觉确认 → DeepSeek 判定
6. Scene 级翻译：同场景页面合并 → 带 Story Memory 的 systemPrompt（本地轮子已验证）
7. Inpainting：POST /pipelines（lama-manga/aot-inpainting），复杂 SFX 按 Text Type 保留+注释（不追求 100% 删日文）
8. Typesetting：koharu-renderer（自动适配/字体回退/竖排）
9. Programmatic QA：块数匹配 / 溢出 / 译后重跑日文检测查残留
10. Vision QA：原图+译图+translation_report → DeepSeek 出 issues+actions
11. Repair Loop：FAIL → 重 OCR / 重翻 / 重擦 → 再 QA → PASS
12. Export：PNG（+PSD 存档）；写 batch_summary / quality_report
```

### 4.4 与本地轮子的关系
- **直接搬**：`koharu_context_wrapper.py`（API 封装）、`build_system_prompt`（prompt 工程）、`manga_translator.py` 的批处理骨架（progress.json/并发/退避）、目录约定。
- **补上**：Story Memory 持久化、Scene 级翻译、Segmentation Mask 擦字、Vision QA、Repair Loop、自动验收（用户的核心诉求——轮子目前依赖人工 review）。
- **重写**：验收与配置部分（外部 D:\我的汉化\scripts 依赖）、硬编码路径参数化。

## 7. 风险与取舍

| 风险 | 说明 | 缓解 |

| 文档与实现脱节 | 本地轮子文档过时 | 以代码为准，重写验收/配置 |
| OCR 人名错误 | 豊姫→星姬 类错误 | 词典比对 + 编辑距离 + 二次视觉确认 |
| 代理/网络 | 本机 Clash 代理干扰 localhost | 已有 NO_PROXY 处理（轮子已验证） |

### 9.2 引擎能力实证（决定方案走向的关键发现）
v0.59.1 引擎 DAG（koharu-app/src/pipeline/engines/）**已实现 preview 设计所需的 mask 机制**：
- `pp-doclayout-v3`（文档版面模型，非漫画专用）→ TextBoxes —— 轮子默认只用了它，**大概率是框外字漏检元凶**
- `comic-text-detector`（漫画专用，bbox+mask）→ TextBoxes + SegmentMask
- `anime-text` / `comic-text-bubble-detector` → TextBoxes
- `comic-text-detector-seg`（needs TextBoxes）→ **像素级 SegmentMask**（只细化已有框，前置漏检则后患无穷）
- `speech-bubble-segmentation` → **BubbleMask**（渲染器安全区排版用）
- `manga-ocr` / `paddle-ocr-vl-1.5` / `mit48px-ocr`（needs TextBoxes）→ OcrText
- `llm` → Translations；`lama-manga`/`flux2-klein`/`aot-inpainting`（needs SegmentMask+BubbleMask）→ Inpainted
- `koharu-renderer`（needs Inpainted+Translations+FontPredictions）→ FinalRender
- REST `PUT /pages/{id}/masks/{role}`（segment|brushInpaint）→ **修复循环可程序化回写 mask**

**推论**：A（框外字）与 D（擦除）同根——ctd_seg 只细化已有框，detector 漏则 OCR/mask/inpaint 全漏。Benchmark A 必须四 detector 同页对比。

### 9.3 Benchmark 方法论（避免人工标注）
- 候选真值 = **4 detector 的并集**（都漏的不计入分母，本就是工具能力边界）
- 真假判定 + OCR 真值 = **describe_image 逐 crop**（VLM 当标注 oracle，同时产出 CER 真值）
- 人工仅抽查「detector 分歧 / VLM 低置信」子集
- 指标：框内对白/框外对白/SFX/背景文字四类 Recall + Precision；OCR 按人名/专名/拟声词/竖排/艺术字分类 CER + Exact Match

2. Benchmark C 评分：区域级 VLM 评分（1-5 + 痕迹/破坏/残留分类，结构化 JSON 入 audit 表）
3. 执行器位置：`E:\manga translator agent\amta\`（新仓库，从轮子拷贝 API 层 + prompt 构建，其余重写）
