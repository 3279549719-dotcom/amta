Stage 4 框外字像素级去除：第一性原理分析与方案设计

分支 feat/stage4-ctd-mask-probe · 2026-09-03 · 基于 BallonsTranslator / comic-translate / koharu 参考实现

执行摘要

核心结论：当前 Stage 4 陷入了一个错误的方向——追求"全页像素级文字分割模型"。但所有专用模型（CTD DBNet、comic-text-detector-seg）都只训练了气泡内黑字白底，对框外字零响应。

认知 shift：RT-DETR-v2 的检测框已经够用了。问题不在"找不到文字在哪"，而在"框内怎么精确圈出文字像素"。在框内，传统图像处理（Otsu 阈值 + 颜色直方图 + 连通域分析）完全够用——这是 BallonsTranslator 和 comic-translate 都验证过的生产级方案。

推荐路径：方案 A（框内传统方法精修，零新模型，立即可以试）→ 验证不够再上方案 B（SAM 框提示分割）→ 最终考虑方案 C（端到端漫画 inpaint 模型）。

二、参考项目深度分析：别人是怎么解决的

2.1 BallonsTranslator：模型给粗先验 + 传统方法精修（最有价值）

BallonsTranslator 的 textmask.py 揭示了一个完全不同的思路：CTD 模型的 UNet mask 不是最终 mask，只是一个先验（pred_mask）。真正的像素级 mask 是在框内用传统图像处理精修出来的。

核心流程 refine_mask()：

  1. 对每个检测框，crop 出框内图像和对应的 pred_mask
  2. get_topk_masklist()：在框内取灰度直方图 top-3 主导颜色，每个颜色 ±30 范围生成候选 mask
  3. get_otsuthresh_masklist()：对每个 RGB 通道做 Otsu 阈值化，生成候选 mask（自动判断黑字/白字）
  4. merge_mask_list()：对每个候选 mask 做连通域分析，逐组件判断：如果加入该组件后与 pred_mask 的 XOR 减小，则保留（即该组件很可能是文字）
  5. 膨胀 5×5 覆盖抗锯齿边缘 + 填洞
为什么这能工作：即使 CTD 对框外字响应弱（pred_mask 稀疏），传统方法（颜色直方图 + Otsu）在框内仍然能找到文字像素。pred_mask 只是用来做"裁判"——判断一个连通域是不是文字，而不是直接作为 mask。这是一个非常聪明的设计。

2.2 comic-translate：完全不用模型，纯传统方法

comic-translate 的 content.py → detect_content_mask_in_bbox() 更激进：完全不用任何深度学习模型，纯传统方法在框内做文字分割。

核心流程：

  1. 灰度化 + Otsu 阈值
  2. 同时考虑黑字（gray < threshold）和白字（gray > threshold），取并集
  3. 连通域分析，过滤规则：
    • 面积 < min_area(10px)：排除噪点
    • 面积 > 50% 框面积：排除大块背景
    • 贴边组件（margin=1px）：排除与框边界相连的背景
    • 标点大小组件（area≥4, w≤6, h≤6）：特别保留
  4. 形态学闭运算连接笔画
为什么这能工作：在框内，文字通常是最显著的连通组件。Otsu 自动找到文字和背景的分界，连通域分析过滤掉背景噪点。这个方法简单但有效，是生产级方案。

2.3 BallonsTranslator inpaint 模型：专门的动漫 inpaint 模型

BallonsTranslator 有一个当前项目没用上的模型：lama_large_512px，来自 dreMaz/AnimeMangaInpainting，是专门针对动漫/漫画训练的 LaMa 大模型。

当前项目用的 koharu lama-manga 可能是不同的模型或版本。如果 mask 精确了，再配合专门的动漫 inpaint 模型，效果应该会显著提升。

三、第一性原理思考：从源头拆解问题

3.1 问题的本质是什么

框外字去除 = 文字像素识别 + 背景修复

这两个子问题的难度是不对称的：

  • 文字像素识别：在框内，文字和背景有明显的颜色/对比度差异。这是一个局部问题，传统方法可以解决。
  • 背景修复：需要理解漫画的网点、线条、纹理、渐变。这是一个全局问题，需要专门的模型。
第一性原理洞察：当前项目把大部分精力花在了"文字像素识别"上（试了 CTD、seg 模型），但这个子问题其实用传统方法就能解决。真正难的是"背景修复"，但因为 mask 太粗糙（矩形），inpaint 模型需要修复的区域太大，导致效果差。先把 mask 做精确，inpaint 的难度会自然下降。

3.2 为什么"全页像素级分割模型"是错误方向

  1. 训练域不匹配：所有公开的漫画文字检测/分割模型（CTD、comic-text-detector）都主要训练气泡内黑字白底。框外字（网点背景、黑底白字、衣服上的字、SFX）不在训练分布内。
  2. 不需要全页分割：检测器已经给出了框。全页分割是在重复检测器的工作，而且精度更低。
  3. 框内更简单：在框内，文字是主要内容，背景相对简单。传统方法（Otsu、颜色直方图、连通域）在框内的效果远好于全页。

3.3 "一个好模型能消灭大多问题"——哪个模型？

用户的直觉是对的：一个好模型能消灭大多问题。但这个模型不应该是"文字分割模型"，而应该是"端到端的漫画文字去除模型"。

两个层次的"好模型"：

  • 层次 1（mask 层）：SAM。通用分割模型，以框为 prompt，零样本就能在框内做精确分割。一个模型解决所有文字像素识别问题。
  • 层次 2（inpaint 层）：专门的动漫 inpaint 模型（lama_large_512px 或扩散 inpaint）。理解漫画网点和纹理，一个模型解决所有背景修复问题。

如果两个都用上，就是：SAM 做精确 mask + 专门动漫 inpaint 模型做修复。这是从源头解决问题的方案。

四、三个方案的详细设计

方案 A：框内传统方法精修 mask（推荐 · 立即试）

零新模型零新依赖速度极快生产验证

核心思路

移植 BallonsTranslator textmask.py + comic-translate content.py 的精华，对每个 text_free 框做框内精修。

具体流程

1. 遍历 text_free 框 → 2. Crop 框内图像 → 3. Otsu + 颜色直方图 → 4. 连通域过滤 → 5. 膨胀+填洞 → 6. 贴回全页 mask

关键算法细节

# 伪代码：框内文字精修
def refine_text_mask(crop_img):
    gray = cv2.cvtColor(crop_img, cv2.COLOR_RGB2GRAY)
    
    # 方法1：Otsu 阈值（同时考虑黑字和白字）
    _, binary_black = cv2.threshold(gray, 0, 255, cv2.THRESH_OTSU + cv2.THRESH_BINARY)
    binary_white = 255 - binary_black
    
    # 方法2：灰度直方图 top-3 颜色范围
    hist = cv2.calcHist([gray], [0], None, [256], [0,256])
    top_colors = get_topk_colors(hist, k=3, color_var=10)
    color_masks = [cv2.inRange(gray, c-30, c+30) for c in top_colors]
    
    # 合并所有候选
    candidates = [binary_black, binary_white] + color_masks
    
    # 连通域分析：过滤太小、太大、贴边的组件
    text_mask = np.zeros_like(gray)
    for cand in candidates:
        components = connected_components_with_stats(cand)
        for comp in components:
            if is_text_like(comp, crop_shape):  # 面积、大小、位置判断
                text_mask |= comp.mask
    
    # 形态学后处理
    text_mask = cv2.morphologyEx(text_mask, cv2.MORPH_CLOSE, (3,3))
    text_mask = cv2.dilate(text_mask, (5,5), iterations=1)  # 覆盖抗锯齿
    text_mask = fill_holes(text_mask)
    
    return text_mask

预期效果

  • 常规黑白漫画框外字：mask 精确率 > 95%，inpaint 质量显著提升
  • 彩色文字 / 低对比度文字：可能不够，需要方案 B 升级
  • 速度：< 0.1s / 框（CPU），几乎不增加总耗时

验证方法

  1. 用 page_11、page_12（问题最明显的两页）做探针
  2. 对比：矩形 mask vs 精修 mask 的 inpaint 效果
  3. 量化指标：mask 像素覆盖率（应该从 10-14% 降到 3-5%）、pixel_diff_ratio、肉眼评估
  4. 跑 5 页端到端验证

方案 B：SAM 框提示像素级分割（中期 · 一个模型通吃）

通用模型零样本复杂背景鲁棒需 GPU

核心思路

用 SAM (Segment Anything Model) 以 RT-DETR 的检测框为 prompt，在框内做零样本像素级分割。SAM 是通用分割模型，对任意背景都有泛化能力。

具体流程

1. RT-DETR 检测框（已有） → 2. SAM box prompt → 3. 多 mask 评分选最优 → 4. 像素级 mask → 5. inpaint

为什么 SAM 是"一个好模型"

  • 泛化能力：SAM 在 1100 万张图像上训练，对任意物体都有分割能力，不限于文字
  • box prompt：正好匹配现有的检测框，不需要重新训练
  • 零样本：不需要漫画文字的训练数据，直接就能用
  • 精度高：在复杂背景（渐变、网点、纹理）上的分割精度远高于传统方法

实现要点

  • 模型选择：SAM ViT-B（最小，~375MB）或 ViT-L（~1.2GB，精度更高）
  • 推理：ONNX Runtime 或 PyTorch，GPU 加速
  • 框内裁剪：为了速度，可以只把框内区域（加 padding）送给 SAM，而不是全页
  • 多 mask 选择：SAM 对一个 box prompt 会返回 3 个候选 mask，选置信度最高的

预期效果

  • 复杂背景（渐变、网点、衣服纹理）：mask 精确率 > 90%
  • 彩色文字 / 艺术字 / SFX：比传统方法更鲁棒
  • 速度：GPU ~0.3-0.5s / 框；CPU 可能 2-5s / 框（较慢）

适用场景

方案 A 对渐变/低对比度/彩色文字不够时的升级路径。或者直接作为主力方案（如果有 GPU）。

方案 C：端到端漫画文字去除模型（根本 · 消灭 pipeline）

质量上限最高从源头解决需找/训模型需 GPU

核心思路

不用"检测 + 分割 + inpaint"三步 pipeline，直接用一个端到端模型输入原图，输出去除文字后的干净图。或者至少用一个专门的动漫 inpaint 模型替代当前的通用 lama-manga。

最可行的子方案：lama_large_512px + 精确 mask

即使不做端到端，把 inpaint 模型从通用的 lama-manga 换成专门的 lama_large_512px，配合方案 A/B 的精确 mask，效果应该会有质的提升。

BallonsTranslator 的 lama_large_512px 配置：

  • inpaint_size: 1536（可选 512/768/1024/1536/2048）
  • precision: bf16（如果 GPU 支持）
  • 模型文件：~800MB（.ckpt）

扩散模型小区域 inpaint 的思路

flux2-klein 整页跑太慢，但如果只在每个 text_free 框的 crop 区域（加 padding）上跑扩散 inpaint，速度可以接受（~5-10s / 框）。质量上限最高，适合对质量要求极高的场景。

六、风险与注意事项

6.1 方案 A 的风险

  • 彩色文字 / 艺术字：Otsu 和颜色直方图对多色文字可能不够，需要多通道分别处理
  • 极低对比度文字：文字和背景颜色接近时，Otsu 可能无法有效分割
  • 文字与背景线条粘连：如果文字压在漫画线条上，连通域分析可能把线条也当成文字
  • 参数调优：颜色范围（±30）、面积阈值、膨胀核大小可能需要根据不同漫画风格微调

6.2 方案 B 的风险

  • GPU 依赖：SAM 在 CPU 上较慢（2-5s/框），需要 GPU 才能实用
  • 模型大小：ViT-L ~1.2GB，ViT-B ~375MB，需要下载
  • 框内多物体：如果框内有文字 + 其他物体（如人物脸部），SAM 可能分割出错误的物体
  • 多 mask 选择：SAM 返回 3 个候选，需要可靠的评分机制选最优

6.3 方案 C 的风险

  • 模型移植成本：从 BallonsTranslator 移植 lama_large_512px 需要适配其模型加载代码
  • GPU 显存：大模型 + 高分辨率 inpaint 需要较多显存（建议 8GB+）
  • 端到端模型缺失：可能没有现成的端到端漫画文字去除模型，需要自己训练

6.4 通用注意事项

  • mask 膨胀量：精修后的 mask 需要适当膨胀（3-5px）以覆盖文字的抗锯齿边缘，否则 inpaint 后可能有残留文字边缘
  • inpaint 区域独立性：多个 text_free 框应该合并 mask 后一次 inpaint，还是分别 inpaint？合并可以减少上下文切换，但可能让不同区域互相干扰。建议先合并试试。
  • 回退机制：精修 mask 失败时（如 mask 全空或全满），应该回退到矩形 mask，保证 pipeline 不中断
  • 可配置参数：阈值、膨胀核、面积阈值等应该做成可配置参数，方便根据不同漫画风格调整

七、总结

最核心的认知 shift：不要追求"全页像素级文字分割模型"。检测器的框已经够用了，问题在框内精修。在框内，传统图像处理（Otsu + 颜色直方图 + 连通域）完全够用，这是 BallonsTranslator 和 comic-translate 都验证过的生产级方案。

立即行动：写方案 A 的探针脚本，用 page_11、page_12 做对比验证。如果效果好，直接接入 Stage 4。这是零成本、零风险、高回报的一步。

中期升级：如果方案 A 对复杂背景不够，上 SAM（方案 B）。一个通用分割模型，以框为 prompt，零样本解决所有文字像素识别问题。

根本解决：换专门的动漫 inpaint 模型（lama_large_512px），最终探索端到端模型。从"修 mask"升级到"直接修图"。

一句话总结：当前的瓶颈不是"没有好的分割模型"，而是"方向错了"。放弃全页分割，在框内用传统方法精修，配合专门的动漫 inpaint 模型——这是从源头解决问题的路径。
