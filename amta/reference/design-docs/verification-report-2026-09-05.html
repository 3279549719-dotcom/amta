决策 A：术语表 pre_scan 自动接入 PASS

问题：orchestrator 引入后丢失了 pre_scan 步骤，术语表为空，サグメ等专有名词被 LLM 乱翻。

修复：translate adapter 翻译前自动检查 work_state.terms，为空时调用 run_pre_scan 扫描已有 canon 锁定术语。

验证项结果
锁定术语数18 个
サグメ探女 ✓
サグ姉探女姐 ✓
接入方式翻译前自动触发，失败降级不阻塞

决策 B：翻译输出数组契约 PASS

问题：LLM 批量翻译时把一条输入拆成两条输出挤占后续 region_id（p14 实际故障：r01 被拆成 r01+r02，后续全部偏移），旧契约只校验数量不校验内容对应性。

修复：LLM 输出从 {"r00":"译文",...} 改为按位置绑定的 ["译文1","译文2",...]，代码侧严格校验 len(output)==len(input)，长度不符直接重试→二分拆分。

验证项结果
p14 canon 区域数12
模拟 LLM 拆条（返回13条）触发重试→二分拆分
LLM 调用次数4 次（首次13条→重试13条→二分各6条）
最终翻译结果数12（=输入数，按位置正确绑定）
r00 / r11均有值，无错位

决策 C：字体大小第一性原理 PASS

问题：decide_direction 用 h/w≥2.2 且字数≤6 两个人为阈值决定方向，47 字窄长框被强制横排，字号压到 19px。

修复：删除 decide_direction，fit_font_size 同时计算横排和竖排（支持多列）的最大可行字号，选字号更大者。零人为阈值。

修复前（旧实现）
19px
横排 14 行，每行 3-4 字
decide_direction 强制横排（字数>6）
修复后（第一性原理）
48px
竖排 3 列，每列 14 字
双方向计算选最优，+153%
验证项结果

竖排最大字号48px（3 列 × 14 字）
最终选择竖排（相等时优先，符合日漫阅读习惯）
