🏭 漫画翻译 · DIY 数字工厂

「文件即状态 · 脚本即工位」—— 用硬盘上的文件夹，搭建可重跑的智能流水线

📌 核心哲学：为什么“文件即状态”最适合DIY？

你不需要数据库、消息队列或微服务。你只需要 操作系统自带的文件系统。

✅ 传统脚本的痛点

  • 内存传参，崩溃后一切重来
  • 改一个模型参数，整章重跑
  • 中间结果无法复用/调试

✅ “文件即状态”的优势

  • 每个步骤的输入/输出都是硬盘上的文件
  • 修改某步后，只删掉对应工件即可重跑
  • JSON/PNG 随时打开检查，调试体验极佳
🎯 终极目标：你的脚本不需要关心“状态管理”。文件存在 = 任务完成，文件不存在 = 需要执行。这就是最可靠的分布式状态机。

📂 项目目录结构（黄金标准）

一个项目对应一个文件夹，所有中间产物（Artifacts）都存放在 artifacts/ 下，完全可追溯。

💡 关键洞察：artifacts/ 文件夹就是你的“数据库”。
脚本之间通过读取和写入这些文件来协作，零内存耦合。

🧠 翻译工位详解：Harness 四维度落地

Anthropic 提出的 Harness 架构（Context / Guardrails / Loop / Tools）完全浓缩在 04_translate.py 中。

① Context Management

👉 关键：不是塞超长Prompt，而是像搭积木一样组装结构化 JSON。

② Guardrails

护栏/校验 防止LLM胡来

👉 必须校验：JSON格式、译文数量匹配、无未翻译日文残留。

③ Loop

循环/自修正 失败后自动重试

👉 for attempt in range(3): 每次失败时把“错误原因”塞回上下文，要求LLM修正。

④ Tools

👉 把 lookup_term、suggest_update 作为函数签名传给 DeepSeek API。

📜 各工位脚本职责（具体指引）

🔹 01_detect.py —— 文字检测

  • 输入：raw/*.png
  • 输出：artifacts/detection.json（包含每个文本框的 bbox 和多边形坐标）
  • 工具：PaddleOCR 或 YOLO 检测模型
  • 缓存逻辑：如果 detection.json 已存在且 raw/*.png 未修改，则跳过。

🔹 02_ocr.py —— 多模型OCR

  • 输入：detection.json + raw/*.png
  • 输出：artifacts/ocr_candidates.json（包含 PaddleOCR、EasyOCR、GOT-OCR 等多个模型的候选结果）
  • 关键点：每个候选都保留 confidence 和 engine 标签，供后续仲裁。

🔹 03_arbitrate.py —— 智能仲裁（首次调用LLM）

  • 输入：ocr_candidates.json + state/glossary.json
  • 输出：artifacts/canon_text.json（标准化的原文，带 region_id）
  • 智能点：当多个OCR结果冲突时，调用 DeepSeek 结合上下文（术语表、视觉crop）做裁决。
  • 注：此脚本也可视为 Harness 的迷你版，但为了聚焦，我们把最复杂的 Harness 留给翻译。

⭐ 04_translate.py —— 翻译工位（完整Harness封装）

这是整个流水线的大脑。它内部实现了前面提到的全部4个 Harness 维度。

输入：canon_text.json + state/glossary.json + state/open_questions.json + 前3页译文

输出：artifacts/translation.json + state/suggestions.json（AI建议的术语更新）

🧩 代码骨架（Python 伪代码） 
def translate_page(page_id):
    # 1. Context Management: 构建结构化上下文
    context = {
        "system": "你是漫画翻译专家...",
        "current": load_canon_text(page_id),
        "history": load_prev_translations(page_id, n=3),
        "knowledge": load_glossary(),
        "uncertainty": load_open_questions()
    }

    # 2. Guardrails + Loop: 带重试和校验的循环
    for attempt in range(3):
        try:
            response = call_deepseek(context, tools=[lookup_term, suggest_update])
            
            # 3. 输出校验 (Guardrails)
            validated = validate_translation(response) # 检查JSON/日文残留
            
            # 4. 保存结果
            save_translation(validated)
            save_suggestions(validated.get("suggestions", []))
            return
        except ValidationError as e:
            # 把错误信息追加到上下文，进入下一次循环 (Loop)
            context["correction_hint"] = str(e)
            continue
    
    # 重试3次仍失败
    mark_failed("translation", page_id)
✨ 这就是Harness的精髓： 把“智能”封装在一个可重试、可校验、带工具函数的闭环中，而不需要外部复杂的编排系统。

🔹 05_inpaint.py —— 擦字与重绘

  • 输入：raw/*.png + detection.json
  • 输出：artifacts/mask.png（蒙版） + artifacts/cleaned.png（擦除文字后的净图）
  • 工具：LaMa 或 Stable Diffusion Inpainting。

🔹 06_typeset.py —— 排版合成

  • 输入：cleaned.png + translation.json
  • 输出：artifacts/final.png（最终成品图）
  • 关键：根据原文坐标自动计算译文换行，选择合适字体大小。

🎮 简易编排器：00_run_all.py

你不需要 Airflow 或 Prefect。一个简单的 Python 脚本，通过检查文件是否存在来控制流程。

import os
import subprocess

def should_run(output_file):
    return not os.path.exists(output_file)

def run_script(script_name, output_file):
    if should_run(output_file):
        print(f"▶️ 运行 {script_name}...")
        subprocess.run(["python", script_name], check=True)
        print(f"✅ {output_file} 已生成")
    else:
        print(f"⏭️ 跳过 {script_name} (文件已存在)")

# 主流程
if __name__ == "__main__":
    run_script("scripts/01_detect.py", "workspace/my_manga/artifacts/detection.json")
    run_script("scripts/02_ocr.py", "workspace/my_manga/artifacts/ocr_candidates.json")
    run_script("scripts/03_arbitrate.py", "workspace/my_manga/artifacts/canon_text.json")
    run_script("scripts/04_translate.py", "workspace/my_manga/artifacts/translation.json")
    run_script("scripts/05_inpaint.py", "workspace/my_manga/artifacts/cleaned.png")
    run_script("scripts/06_typeset.py", "workspace/my_manga/artifacts/final.png")

    print("🎉 全部完成！")
💡 断点续跑技巧： 如果 04_translate.py 运行失败，你只需要修好代码，然后 手动删除 translation.json，再次运行 00_run_all.py，它会自动从翻译工位重新开始，而不会重跑检测和OCR。

🌱 上下文演进：如何让AI“自由探索”又不翻车

你之前担心的“只注入静态Prompt”，在这里被完美解决。我们通过 “建议-审批” 机制，让AI在翻译过程中持续学习。

sequenceDiagram participant User participant Script as 04_translate.py participant AI as DeepSeek participant State as state/glossary.json Script->>AI: 提供当前页 + 现有术语表 AI->>AI: 翻译中发现新角色 "豊姫" AI->>Script: 返回译文 + suggest_update("豊姫", "丰姬") Script->>State: 写入 suggestions.json Script->>User: 提示 "有1条术语建议待审核" User->>State: 手动确认，合并入 glossary.json Note over State: 下一轮翻译自动生效

🔹 低风险建议（自动批准）

  • 数字、日期、专有名词（如“1000年”）
  • 置信度 > 95% 的术语统一

🔸 高风险建议（人工审批）

  • 核心角色名字（影响剧情理解）
  • 涉及文化背景的翻译（如“忍者”→“武士”）
🏆 结果： 翻译10页后，glossary.json 越来越完善。AI不再“自由探索”互联网，而是在你给它划定的“知识圈”里高效工作，既保证了质量，又满足了“动态更新”的需求。

阶段 目标 核心任务

第2周 接入智能仲裁 实现 03_arbitrate.py，用DeepSeek解决OCR冲突。

🎯 最重要的建议： 不要一次性写完所有代码。从 00_run_all.py 开始，每次只实现一个工位，确认它的输入输出符合Contract，再写下一个。这种“增量式”开发，会让你对每一个环节都有深刻理解。
