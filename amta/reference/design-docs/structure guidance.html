Digital Factory Architecture

把漫画自动翻译设计成一座数字工厂：稳定的机械加工线 + 可插拔的智能工位 + Artifact Contract + 可重跑的生产节点 + QA 闭环。

核心结论：不要把 Dynamic Story Workflow 当成唯一流程。它只是一个 selectable pattern。整个系统真正稳定的骨架应该是：Assets → Artifacts → Processing Stages → State/Context → QA → Re-run。

稳定层

Page Asset、Detection、OCR、Mask、Inpainting、Typesetting、QA 等都应该有清晰输入/输出，可以独立缓存和重跑。

智能层

DeepSeek 负责需要推理的任务：OCR arbitration、上下文选择、翻译、State 更新、异常处理。Vision 是它可按需调用的工具。

1. 工厂架构的六个原则

① Artifact First

每个工位都生产正式 Artifact，而不是在内存里把结果直接塞给下一段代码。

② Single Responsibility

一个 stage 解决一个主要问题，不让 OCR 顺便翻译，也不让 Inpainting 顺便做排版。

③ Re-runnable

任何中间阶段失败，都应该能够从最近的有效 Artifact 重新执行，而不是整章重跑。

④ Optional Intelligence

Agent/vision 是可以插入的智能工位，不是所有路径都必须经过它。

⑤ State Outside Context

长期状态存为独立 Artifact，不依赖某次 LLM conversation 才能继续。

⑥ Verification at Boundaries

每个重要 stage 的输出都可以 schema-check；最终结果再进行程序 QA + Vision QA。

字段用途

6. Detection + OCR：机械材料加工

PageAsset
   │
   ▼
Text Detection
   │
   └── DetectionArtifact
          ├── region_id
          ├── bbox / polygon
          ├── region_type
          └── detector_version

DetectionArtifact
   │
   ├──→ OCR-A ─┐
   ├──→ OCR-B ─┼→ OCRArtifact
   └──→ OCR-C ─┘

当前项目的实验已经说明：Vision + DeepSeek 在文字区域发现方面很强，而 OCR 可以由多个专用模型提供候选。最佳架构不是让一个模型独占真值，而是保留候选证据。

如果用户只上传一张图片，Story State 可以为空；如果用户持续上传同一作品，它可以逐渐成长。这样不会把产品锁死在“连续章节翻译”场景。

9. Translation Agent：只在需要推理的地方集中智能

Input:
  CanonicalTextArtifact
  + PageAsset
  + optional StoryState
  + optional VisionTool

Process:
  1. determine relevant context
  2. identify speaker / references
  3. translate scene coherently
  4. update state only when useful

Output:
  TranslationArtifact
  + StateUpdateArtifact
关键：Translation Agent 不负责检测、OCR、擦字、排版；它只负责语义生产和需要推理的决策。

12. 可重跑与缓存：工厂设计里比 Agent 更重要

Artifact输入发生变化时才重跑
DetectionArtifactsource image / detector version / parameters
OCRArtifactcrop / OCR model version / parameters
CanonicalTextOCR candidates / arbitration policy / relevant state
Translationcanonical text / context / translation model / rules
Masksource image / region / segmentation model
Inpaintingsource + mask / inpainting model
Typesettingclean image + translation + layout rules
这意味着换一个 OCR 模型，不必重跑 detection；改译文，也不必重新 inpaint。

13. Failure Isolation：让错误停在工位

OCR-B failed
   ↓
OCRArtifact B = FAILED
   ↓
OCR-A / OCR-C remain VALID
   ↓
Arbitration can continue with available candidates

Inpainting failed
   ↓
CleanImageArtifact = FAILED
   ↓
Translation remains VALID
   ↓
Retry inpainting only

每一个 stage 都需要状态：

PENDINGRUNNINGVALIDFAILEDSTALE

14. 不连续图片：把“项目上下文”与“图片顺序”解耦

Project
 │
 ├── Page 017  ─┐
 ├── Page 033  ─┼──→ Story State A
 └── Page 099  ─┘

Another upload
 │
 ├── Page 003  ─┐
 └── Page 004  ─┴──→ Story State B

系统不要根据文件名强行推断连续剧情。页面是否属于同一 Story State 可以是：

  • 用户指定
  • 项目默认关联
  • Agent 根据视觉/文本证据提出候选
  • 未来再由用户确认

15. Dynamic Workflow 只是一个可选 Pattern

Pattern适合场景特征
Single Page用户只翻一页无 Story State，直接 Page → Translate
Batch Pages几张不连续图并行 Page Pipeline，共享或不共享 State
Sequential Story连续章节Story State 持续更新
Review & Repair高质量生产QA → Repair → QA
Human-in-the-loop困难页/重要作品Agent 提交疑点，人确认后继续
产品架构应该支持这些 Pattern，而不是强迫所有输入都走 Dynamic Story Workflow。

17. 外部架构的共同点

Google / Gemini

Google 近期对生产级 Agent 的架构强调：Agent 的 Think→Act→Observe 循环之外，需要 orchestration layer 管理通信和数据流，并把 session state、memory、tool use 和安全/质量机制放在外围。Google 还强调 durable execution、checkpoint/resume 和状态机来支撑长期运行。citeturn793974search9turn793974search4turn793974search12

Anthropic

Anthropic 的长期 Agent 研究强调用 structured artifacts 在不同 context windows/session 之间传递上下文；其 2026 年 harness 设计文章进一步展示了 planner/generator/evaluator 与 artifact handoff 的模式，同时提醒要持续删掉随着模型进步而变得多余的 harness 假设。citeturn793974search7turn793974search3turn793974search2

OpenAI

OpenAI 的 Harness Engineering 强调 repository/environment、feedback loops、invariants、custom lint 和 structural tests；核心不是让 Agent 每一步都走固定脚本，而是把重要的工程不变量变成 Agent 能发现、工具能执行、测试能验证的环境能力。citeturn0search0

18. 对你的数字工厂最有价值的抽象

外部实践我们借什么不照搬什么
Google Agent Platformstate、durability、orchestration、resume企业级 runtime / microservice fleet

20. 真正的下一步：Artifact Contract

不要急着写完整系统。下一阶段先把每个工位的 contract 定下来。

ArtifactProducerConsumer核心字段可否重跑
PageAssetIngestorDetectionpage_id, source hash, dimensions—
DetectionArtifactDetectorOCR / Arbiterregion_id, bbox, type, model_versionYes
OCRArtifactOCR enginesArbitercandidate text, confidence, engineYes
CanonicalTextArbiterTranslationsource text, region, resolutionYes
StoryStateTranslation AgentTranslation Agent / Arbiterentities, terms, scenes, relationsVersioned
TranslationArtifactTranslation AgentTypesetter / QAtarget text, region, speaker, styleYes
QAArtifactQAOrchestratorstatus, issue, severity, repair targetYes
当这些 contract 定下来，DeepSeek、Qwen、PaddleOCR、任何 OCR 或 Inpainting 模型都可以替换，而工厂本身不需要重写。
