# 流水线可追溯性调研存档（2026-08-26）

> 来源：firecrawl 调研（LLM agent observability + data pipeline provenance 两个方向）。
> 用途：AMTA 串自动化（00_run_all）的可追溯设计参考。决策：个人 DIY 项目采用轻量方案，见文末。

## 一、LLM/Agent 可观测性（Langfuse / LangSmith / OpenTelemetry GenAI 共识）

### 核心结论
1. **step-level tracing 是最小可用信号**：agent 的失败是语义性的——"跑得完美但结果错了"，二进制 up/down 健康检查没用。每个步骤（model 调用、工具调用、检索、推理跳）都要记录输入/输出/耗时/决策，拼成可重放的 trace。
2. **每次运行要有 run_id + 代码版本（git hash）+ 模型 + token 用量**：从任何产物追溯到"哪个 commit 的哪次运行"。
3. **guardrail 决策和 override 都要记录**（审计轨迹）：谁在什么时候驳回了什么、改了什么。

### 工具链盘点
| 工具 | 形态 | 备注 |
|---|---|---|
| Langfuse | 自托管平台（ClickHouse）/云 | 2026 被 ClickHouse 收购；MIT（ee 除外） |
| LangSmith | 托管 SaaS | LangChain 系，RunTree 层级 |
| Arize Phoenix | 自托管，OpenTelemetry 原生 | Elastic License 2.0 |
| OpenLIT / OpenLLMetry | OTel 插桩库 | 一键 instrument |
| OpenTelemetry GenAI semconv | 标准（仍在 Development） | gen_ai.* span 属性，防 vendor 锁定 |

## 二、数据管线 Provenance（DVC / Pachyderm / MLflow 共识）

1. **"If it's not logged or versioned, it didn't happen."**
2. **run 元数据**：唯一 run ID + 参数 + metrics + 代码版本（git hash）+ 数据版本（checksum）+ 产物引用。
3. **lineage 血缘**：记录"用了哪个文件（带 checksum）产出了哪个文件"。
4. DVC/Pachyderm：强制 pipeline 结构 + 自动记录 provenance（对个人项目过重）。

## 三、裁剪裁决：企业级 vs 个人 DIY

### 砍掉（企业级才需要）
- ❌ OpenTelemetry semconv 标准化 / vendor 中立——个人项目无换 vendor 需求
- ❌ Langfuse/LangSmith/Phoenix 平台——自托管要数据库/Docker，个人项目过重
- ❌ 采样策略、tail-based sampling——无流量压力
- ❌ PII 脱敏治理、RBAC、数据驻留合规——无多租户/合规需求
- ❌ 分布式 trace 上下文传播——单机
- ❌ DVC 式数据版本框架——git 已够，个人项目不追 bit-for-bit 复现
- ❌ 成本告警体系——个人看 invoice 即可（token 计数可顺带记录，不建告警）

### 保留（个人项目要的可追溯可溯源）
- ✅ **每步记录**：哪一步、什么输入、什么输出、什么参数、什么模型、状态
- ✅ **失败锚点**：卡在哪一步、违反什么契约（reason）
- ✅ **模型调用过程**：每页翻译的 LLM 调用 + 工具调用摘要（"每一次相关的调用过程"）
- ✅ **断点续跑依据**：文件存在=跳过；log 记输入文件名/大小，排查时可人工对比
- ✅ **git commit 记入 log**：知道哪次运行是哪版代码

## 四、AMTA 落地设计（轻量 v1）

```
workspace/<work_id>/state/pipeline_log.json
{
  "work_id": "...",
  "runs": [
    {
      "run_id": "uuid",
      "started_at": "...",
      "git_head": "d585aa3",
      "trigger": "full | page:11 | repair:page_2_u08",
      "steps": [
        {"step": "01_detect", "page": "page_10", "status": "ok", "input": "11.jpg", "output": "detection.json", "n_boxes": 12, "duration_s": 3.2},
        {"step": "02_ocr",    "page": "page_10", "status": "ok", "input": "detection.json", "output": "canon_text.json", "n_regions": 9},
        {"step": "03_translate", "page": "page_10", "status": "ok", "model": "deepseek-v4-pro", "tools_calls": 3, "trace": "trace_page_10.json"},
        {"step": "semantic_check", "page": "page_10", "status": "pass", "model": "deepseek-v4-flash-vision-exp", "scores": {...}},
        {"step": "repair", "status": "ok", "rounds": 1, "ticket": null}
      ],
      "failed_step": null
    }
  ]
}
```

- 每步一个 span 记录（append，不覆盖）
- 03 加 `--trace`：每页 LLM/工具调用摘要落盘（探针转正，成本极低）
- 失败时 `failed_step` 指向卡点 + reason，配合 needs_review 工单
- 不引入任何外部服务/数据库；纯 JSON 文件即状态
