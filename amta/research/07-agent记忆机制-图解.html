一、改造前后：从坟场到闭环

改造前 · 三处断裂

写入自动化，读取零机械化

  • `.remember` 由 claude-remember 插件 hook 自动写入，但 lessons / ADR / progress 从未被注入
  • 注入只在会话开头发生一次，长会话中被稀释；压缩（compaction）后记忆彻底蒸发
  • CLAUDE.md 加载表按任务名枚举，踩坑场景对不上触发词；4 行指向不存在的 research/ 幽灵路径
改造后 · 推 + 拉 + 护

每个接手 agent 必然带着记忆开工

  • startup 注入记忆包 ≤1.5KB（handoff + lessons 标题行 + 启发式）——不靠自觉
  • compact 重注入——上下文被压缩的瞬间，记忆包自动回来
  • just-in-grep 打捞——遇到症状才查，memory_search 返回路径+行号，read 展开全文
  • linter 进 fastcheck——记忆腐坏（过期/悬空/幽灵路径/超预算）在提交前被拦截

三、每层在什么时刻生效

时机层发生什么强制等级
会话启动 / resume第0层 基线CLAUDE.md、AGENTS.md 自动加载：核心事实 + 问题域启发式表（"遇到 X → 先 memory_search Y"）prompt 级（软）
会话启动（startup）推送层hook 注入记忆包 ≤1.5KB：handoff（now/recent）+ lessons 最近 5 条标题行 + 启发式一行。agent 零动作即见hook 级（机械）
上下文压缩（compact）推送层瘦版记忆包 ≤0.5KB 自动重注入——长会话"看两眼就忘"的机制性解药：压缩 = 记忆丢失点 = 重注入点hook 级（机械）
工作中遇到症状 / 决策前拉取层just-in-grep：memory_search（全知识地产正则检索，返回路径+行号+命中行）→ memory_recent（最近增量）→ 内置 read 展开全文工具级（半机械）
编码期 / 提交前护栏层pytest 锁死 hook 脚本行为（stdin JSON → stdout）；memory_lint 并入 fastcheck：recent>7 天 FAIL · today 悬空 WARN · 索引幽灵路径 FAIL · 注入包>10K FAILtest/lint 级（机械）
审计期（每 2-4 周）护栏层冷启动探针挂 audit：新会话问"上次停在哪 / 某坑怎么解"，命中即 PASS——记忆活性的定期体检流程级

四、Progressive Disclosure vs Just-in-Grep：区别与共存

Progressive Disclosure

管"给多少"——token 粒度策略。信息按层级展开：索引 → 摘要 → 全文，每层只暴露让 agent 决定"要不要往下看"的最小量。

  • CLAUDE.md 索引行是第一层
  • memory_search 命中行是第二层
  • read 全文是第三层
  • claude-mem 的 search→timeline→read 是同款范式
vs
Just-in-Grep

管"何时给"——时机策略。不预塞任何内容；等 agent 实际遇到问题（报错、决策、陌生流程）才现场检索。

  • 对应 Claude Code 原生 grep/glob 哲学
  • 前提：agent 得知道有东西可搜（否则就是坟场）
  • 前提：检索工具得返回可行动的结果（路径+行号，而非全文）
结论：正交，天然共存，且必须组合。Progressive Disclosure 回答"每一步暴露多少"，Just-in-Grep 回答"什么时候触发暴露"——一个粒度轴、一个时机轴，在同一条检索路径上叠加：注入层 push 索引（agent 零动作知道有这张牌）→ 遇到症状时 just-in-grep 拉命中行 → read 展开全文。单用 PD 没有 JIT 触发就是现在这座坟场（索引躺着没人展开）；单用 JIT 没有 PD 就是 token 灾难（要么预塞全文要么无从搜起）。
