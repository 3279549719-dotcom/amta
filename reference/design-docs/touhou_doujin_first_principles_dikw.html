Touhou Doujin Manga Translation

从第一性原理与 DIKW 出发，把“通用漫画翻译器”收缩成一个更同质化、更可验证的 Touhou Project 同人志翻译系统。

核心结论：不是做一个无限泛化的漫画 Memory，而是把 Touhou Canon Knowledge + 当前 Doujin Work State + Current Evidence 组合成一个持续更新、可修正的翻译上下文。

机械层

Text Detection、OCR Ensemble、OCR Arbitration、Segmentation、Inpainting、Typesetting、Programmatic QA。

Agent 层

DeepSeek 负责“现在知道什么、还缺什么、应该看什么、相信什么、怎么翻译、状态怎么更新”。

1. 为什么从“通用漫画”缩到“同人志”

商业连载

  • 长期连续
  • 几十到几百话
  • 大量角色与关系
  • 剧情状态长期变化
  • 早期信息可能长期影响后续翻译

同人志

  • 通常更短、更局部
  • 角色集合更小
  • 常围绕一个冲突、关系或笑点
  • 读者往往已经知道原作世界
  • 作品自己的“新世界状态”通常比长篇商业连载简单
通用漫画更需要完整世界模型；Doujinshi 可以优先研究“共享 IP 先验 + 当前本子状态”。

2. 为什么 Touhou 又是一个特别好的实验场

Touhou 的特殊性不是“它简单”，而是拥有大量高复用的共享语义知识。

Touhou Knowledge
├── Characters
├── Locations
├── Organizations / Groups
├── Terms
├── Canon relationships
└── Common speech characteristics

东方同人志往往不需要从零解释“霊夢是谁”“紅魔館是什么”。因此 Agent 可以从强先验状态开始，而不是每一本都从空白世界开始。

但是：Canon Knowledge 只是 prior，不是当前作品的绝对真相。

3. 最关键：Canon ≠ 当前 Doujin 的 Truth

Touhou Canon Knowledge
        ↓
      Prior
        ↓
Current Doujin Evidence
        ↓
     Work State
        ↓
Translation Decision

同人志可能改变人物关系、语气、性格，甚至采用 IF / parody / AU。

优先级建议：
当前作品直接证据 ＞ 当前 Work State ＞ Touhou Canon Prior ＞ LLM 单纯猜测。

4. DIKW 第一层：Data

最底层是漫画实际产生的数据。

Raw image
 ↓
Text detection boxes
 ↓
OCR candidates
 ↓
Coordinates
 ↓
Page / region metadata
 ↓
Visual evidence

你当前的 Text Detection、三路 OCR、OCR Arbitration 本质上属于 Data acquisition / normalization。

这一层应该尽量机械化，因为目标不是理解故事，而是可靠取得证据。

5. DIKW 第二层：Information

把 Data 组织成“当前页面发生了什么”。

{
  "speaker": "霊夢",
  "target": "魔理沙",
  "text": "……",
  "type": "dialogue",
  "page": 17,
  "region": "r08"
}

这一层关心：谁说了什么、谁和谁同场、文本类型、空间关系和阅读顺序。

6. DIKW 第三层：Knowledge

Touhou Canon Knowledge

长期稳定的 franchise knowledge。

Current Work State

这一本 Doujinshi 已经建立的角色、术语、关系和设定。

Knowledge
├── Canon Prior
└── Work State
    ├── confirmed characters
    ├── canonical terms in this work
    ├── current relationships
    ├── current scene
    └── established local facts

两者不能混成一个表，否则同人作品的作者自定义会被“原作知识”压回去。

7. DIKW 第四层：Wisdom

在这个系统里，Wisdom 不是“知道更多”，而是：

知道什么时候应该相信什么，以及还缺什么证据。
Canon says:
Reimu is usually casual.

Current doujin:
Reimu suddenly speaks very formally.

Weak model:
“Reimu should be casual.”

Better Agent:
“当前作品表现可能是有意的人物状态变化。”
↓
use current evidence
↓
translate accordingly

Wisdom = 证据优先级 + 状态判断 + 工具选择。

8. 不需要大型 Story Graph：先做 Work State

work_state.json
├── characters
├── terms
├── relationships
├── current_scene
├── recent_context
└── open_questions

第一版不需要完整 Entity Graph、复杂时间线、事件图谱或独立 Memory Service。

目标是让状态随着作品推进自然增长，而不是提前构建一个“完美世界模型”。

9. Dynamic Discovery：不要一次性把所有知识塞给模型

Unknown
  ↓
Candidate
  ↓
Observed again
  ↓
Confirmed
  ↓
Refined
  ↓
Possibly contradicted
  ↓
Revised

角色

第一次遇见可能只有视觉身份；出现名字后建立 canonical entity。

术语

第一次出现只是普通词；反复出现并成为世界观核心后才进入 glossary。

关系

从当前证据推断，而不是假设永久不变。

场景

随着页面推进持续更新，而不是开局定义完整剧情。

10. Evidence Tracking：为什么要知道“我为什么这么认为”

Story State 里的信息并不是同一种“真”。

状态例子意义
Confirmed页面明确写出“綿月豊姫”强事实
Inferred根据语气推测某角色正在怀疑另一角色模型推断
Candidate暂时无法确认身份等待后续证据
{
  "fact": "豊姫 is 永琳's disciple",
  "status": "confirmed",
  "source": ["page_4:text_13"]
}

{
  "fact": "豊姫 distrusts 永琳",
  "status": "inferred",
  "confidence": 0.72,
  "source": ["page_21:text_07"]
}
Evidence Tracking 不是给每句话加脚注，而是让 Agent 知道：哪些是证据确认的事实，哪些只是自己的当前信念。

11. Relationship / Identity 都允许变化

friend

关系变化会影响称呼、敬语、句尾、语气和措辞。

12. 产品现实：用户不一定一次上传整本漫画

输入情况产品模式
单页Single-page mode：没有历史也可以运行。
连续几页Incremental mode：逐步积累 Work State。
过几天继续Resume mode：从持久 State 恢复。
补传旧页Reconciliation mode：允许新证据修正旧状态。
乱序页Out-of-order mode：依据 page identity，而不是上传顺序。
新作品New-work mode：建立独立 Work State。
完整漫画连续阅读是增强能力，不是系统运行前提。

13. 最实用的上下文模型：三层就够

TOUHOU CANON
    ↓
Relevant Work State
    ↓
Current Evidence
    ↓
DeepSeek
层内容
Touhou Canon与当前人物/地点/术语相关的稳定先验。
Work State当前本子已经确认或推断的局部状态。
Current Evidence当前页 OCR、坐标、视觉 crop、最近对白。
不是把整个 Touhou Wiki + 整本漫画一次性塞进 Prompt，而是只取当前任务需要的切片。

14. Vision Model 的真正位置：Agent 的“眼睛”

Mechanical Vision
→ 稳定完成 detector / OCR / image processing

Agent Vision
→ DeepSeek 按需调用
→ 解决 semantic ambiguity

典型场景

OCR candidates:
A = 豊姫
B = 星姫
C = 豊妃

Work State:
豊姫 = known character

DeepSeek still uncertain
        ↓
Vision Tool
        ↓
inspect crop / page
        ↓
Arbitration

Wisdom 不是额外的数据库。它是 Agent 在 Data、Information、Knowledge 与当前作品证据之间进行判断的能力。

20. MVP：把战线真正缩短

第一版只验证：

  1. Touhou Canon Knowledge 能否减少基础设定注入。
  2. Work State 能否逐页自动生长。
  3. 单页输入在没有历史时仍能翻译。
  4. 连续输入时翻译一致性是否提高。
  5. 补传旧页后系统是否能够修正错误状态。
  6. OCR Arbitration 是否因为 Touhou / Work State 更可靠。
如果这些成立，你已经证明了真正的 Agentic 核心。之后再考虑更复杂的 entity resolution、relationship history、evidence graph。

21. 最终定义

你不是在做“一个更大的漫画翻译 Prompt”。
Touhou Canon Knowledge
        +
Current Doujin Work State
        +
Current Page Evidence
        ↓
DeepSeek
        ↓
Decide what is known / unknown
        ↓
Retrieve / inspect / infer
        ↓
Translate
        ↓
Update Work State
        ↓
Next page / next user request

表面上，这是一个 Touhou 同人志翻译器；从第一性原理看，它是在研究一个拥有强先验知识、面对不完整输入、能够持续构建局部世界状态，并根据新证据不断修正自身判断的长期 Agent。

22. 当前设计底线

坚持暂时不做
文件即状态数据库化
脚本即工位复杂 workflow engine
Touhou Canon 作为 prior把 canon 当成当前漫画真相
Work State 渐进生长预构建完整 Story Graph
Agent 按需看图每一步都重新调用 Vision
单页可运行要求用户一次上传整章
