D. 提出的 Finish 循环（已实现）

生命周期（cycle-close skill = /finish）

任务完成
  ↓
Step 1 复读任务（目标/验收/约束/受影响文件）
  ↓
Step 2 审查 diff（无关改动/死代码/调试代码/生成物/架构越界）
  ↓
Step 3 确定性验证（check → test → fastcheck；动引擎加 smoke）
  ↓
Step 4 修复（失败→诊断→修复→重跑，不停在报错）
  ↓
Step 5 反思（A 无可复用 / B 一次性 / C lesson / D 规则 / E 不变量）
  ↓
Step 6 知识晋升（lesson → rule → test/hook）
  ↓
Step 7 只更新真正变化的工件（progress/lessons/decisions/CLAUDE/tests/hooks）
  ↓
Step 8 git 落盘（明确 add → commit → push → ahead=0 behind=0）
  ↓
Finish Report（结构化，给下一个 Agent）
数据真实性门禁（先于落盘）：要落盘的数字必须有证据文件（output/*.json、脚本输出）；拿不出证据只写"待验证/规划"。这正是防止"假 CER 0.11 落盘"的机制。

E. 提出的三级护栏（已实现）

Level 1 — 编码期（秒级）

npm run fastcheck → scripts/fastcheck.py

  • compileall（src+scripts 语法门）
  • 确定性单测（tests/，纯数据）
  • 输出 JSON schema 校验

不跑 koharu / 网络，编辑后随手跑，低摩擦。

Level 2 — pre-commit

.githooks/pre-commit

  • 跑 fastcheck（语法 + 单测 + schema）
  • 失败即阻止提交

确定性、秒级，不阻塞。

Level 3 — pre-push

.githooks/pre-push

  • compileall + 全量单测
  • koharu 可达则跑 smoke，不可达则提示跳过（不阻塞）

离开机器前的强本地门禁，可比 pre-commit 慢。

安装与命令

npm run hooks:install   # git config core.hooksPath .githooks
npm run fastcheck       # Level 1 编码期
npm run finish          # check + test（发布前）
npm run audit           # 确定性审计

hooks 为 POSIX sh（Git Bash 可用）；Windows 下通过 core.hooksPath 激活。

F. 提出的 Audit（已实现）

范围与频率

频率：每 2-4 周或每个大里程碑后跑一次（不是每次任务都跑）。

命令：npm run audit（确定性部分）+ audit skill（判断部分）。

维度检查
MemoryCLAUDE.md 是否过大（>120 行）；规则重复；lessons 过时/自相矛盾
Architecture是否漂移；模块边界；新依赖是否合理（零运行时依赖）
Verification反复失败是否缺回归；重要不变量是否只在散文里
Automation手写规则能否转 test/lint/hook；校验是否跑错生命周期
Hygiene死文件/重复/临时产物/被忽略文件意外提交

产出"Top 3 actions"可行动建议，不是巨型报告；审计是咨询不是门禁（exit 0）。
