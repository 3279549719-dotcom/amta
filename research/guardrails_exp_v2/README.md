# Guardrails v2 实验 — 三态 VLM (keep/fix/drop)

## 实验配置
- 检测器：RT-DETR-v2 (conf=0.3)
- OCR：Baberu OCR (ONNX int4)
- VLM：qwen3.5-omni-plus @ DashScope（页面级三态判断）
- LM：deepseek-v4-flash @ DeepSeek（纯文本翻译）
- 样本：10页 [0, 1, 2, 5, 6, 11, 12, 14, 18, 32]
- 分支：feature/guardrails-vlm-filter

## 三阶段产出

| 阶段 | 文件 | 说明 |
|---|---|---|
| ① 检测层+OCR层 | `01_detect_and_ocr_conf03_sample10.json` | RT-DETR-v2(conf=0.3) 检测 + Baberu OCR，10页样本，104框/1640字 |
| ② 翻译层 | `02_translation_v2_tri-state.json` | 规则过滤 + 三态VLM(keep/fix/drop) + LM翻译，最终73框 |

## 关键数据

| 指标 | 数值 |
|---|---|
| 原始检测框 | 104 |
| 规则过滤 | 24 (23.1%) |
| VLM keep | 56 |
| VLM fix（修正OCR错误） | 17 (21.2% of rule-kept) |
| VLM drop | 7 (8.7%) |
| 最终翻译框数 | 73 |
| 总过滤率 | 29.8% |

## 已知问题
1. **术语表未接入**：实验脚本的 lm_translate 是简化版，未注入项目术语表和上下文，导致人名翻译不一致（如 page_14 "サグメ" 翻成"撒古美"而非"探女"）
2. **无框字召回不足**：page_05 "設定解説"下面的正文未被检测到（检测层问题，非VLM问题）
3. **翻译连续性**：每页独立翻译，无前后文上下文

## 结论
**v2 是当前最佳方案**（用户确认 2026-09-01）。三态 VLM 的 fix 能力解决了 v1 二态方案"只有丢弃权没有修正权"的核心问题，把 17 个 OCR 识别错误的框从"被误杀"变成"被修正后保留"。
