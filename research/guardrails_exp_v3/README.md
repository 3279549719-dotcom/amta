# Guardrails v3 实验 — 三态 VLM + 检测层降阈值 (conf=0.2)

## 实验配置
- 检测器：RT-DETR-v2 (conf=0.2，从0.3降低以召回更多无框字)
- OCR：Baberu OCR (ONNX int4)
- VLM：qwen3.5-omni-plus @ DashScope（页面级三态判断）
- LM：deepseek-v4-flash @ DeepSeek（纯文本翻译）
- 样本：10页 [0, 1, 2, 5, 6, 11, 12, 14, 18, 32]
- 分支：feature/guardrails-vlm-filter

## 三阶段产出

| 阶段 | 文件 | 说明 |
|---|---|---|
| ① 检测层+OCR层 | `01_detect_and_ocr_conf02_sample10.json` | RT-DETR-v2(conf=0.2) 检测 + Baberu OCR，10页样本，179框/2158字 |
| ② 翻译层 | `02_translation_v3_conf02_tri-state.json` | 规则过滤 + 三态VLM(keep/fix/drop) + LM翻译，最终93框 |

## 关键数据

| 指标 | 数值 | vs v2(conf=0.3) |
|---|---|---|
| 原始检测框 | 179 | +75 (+72%) |
| 规则过滤 | 75 (41.9%) | +51 |
| VLM keep | 60 | +4 |
| VLM fix（修正OCR错误） | 33 (31.7%) | +16 |
| VLM drop | 11 (10.6%) | +4 |
| 最终翻译框数 | 93 | +20 (+27%) |
| 总过滤率 | 48.0% | +18.2pp |

## 降阈值效果分析
- conf=0.2 比 conf=0.3 多检出 75 框，但其中 51 框被规则过滤（大部分 extreme_aspect 扁条/竖条误报）
- 净增 24 框进入 VLM，其中 VLM fix 了 16 个、keep 了 4 个、drop 了 4 个
- 最终翻译多 20 框，主要来自 page_06(+9)、page_12(+4)、page_14(+3)、page_02(+3)

## 已知问题
1. **VLM fix 质量需人工验证**：33个fix中有部分是SFX类修正（如 page_02 "そういうことですが、"→"チャッ"），VLM可能在脑补文本，需人工确认
2. **术语表未接入**：同v2，实验脚本未注入术语表和上下文
3. **page_05 无框字仍未解决**：conf=0.2 只比 conf=0.3 多1框(9vs8)，角色介绍列表的正文召回不足是检测模型本身的问题，降阈值帮助有限
4. **规则过滤压力大**：41.9%的框被规则过滤，说明降阈值引入了大量误报，规则过滤的准确性变得更关键

## 结论
v3 最终翻译框数最多(93)，但 VLM fix 数量(33)也大幅增加，其中部分 fix 的质量存疑（SFX脑补）。用户确认 v2 为当前最佳方案，v3 作为备选方案保留，待人工验证 fix 质量后再决定是否采用。
