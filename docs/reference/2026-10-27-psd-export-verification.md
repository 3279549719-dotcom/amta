# PSD 导出优化：独立复核与收尾

2026-10-27；工作分支 `eirin/psd-export-optimize`。核心优化已由接力方合入并推送 main；本次在接力 worktree 完成剩余修复，经检查后快进同步主分支。

## 核心结论

批量 ActionDescriptor 建层已经接入正式导出器。它保留 Photoshop DOM 的字体、抗锯齿及段落默认值，同时同步 size/impliedFontSize，避免直接创建描述符改变渲染。保留 `AMTA_PSD_LEGACY=1` 进程环境变量作为旧路径回退。

独立读取接力产出的 12 张 PSD 预览与 metadata，6 对像素完全相同、图层标量属性完全相同；冻结 clean/typeset 的 6 个 SHA-256 均匹配。未把内部描述符键省略推广为任意编辑后行为完全相同的保证。

| 同一冻结页 | CLI 原版 → 优化版中位数（5 次/变体） | COM 原版 → 优化版中位数（2 次/变体） |
|---|---|---|
| 5，2 文字层 | 5.04 → 2.54 秒 | 30.37 → 11.08 秒 |
| 3，7 文字层 | 11.54 → 4.04 秒 | 36.10 → 11.36 秒 |
| 19，6 文字层 | 10.55 → 3.54 秒 | 22.85 → 8.22 秒 |

CLI 配对样本中，三页中位数之和降低约 63%，满足原定至少 40% 的目标。两个实验不在同一时间进行，不能横向拿表中 CLI 与 COM 数值判断哪种传输更快。COM 只在 benchmark 中实现；GUI 仍然使用 `Photoshop.exe -r`，仍存在启动/交接长尾，不能保证每次点击都在上述中位耗时内完成。未把冷启动问题宣称为已解决。

逐次计时、重新计算的中位数和独立等价检查见 [数值证据](2026-10-27-psd-export-evidence.json)。作品、PSD、原始预览仍保留在本地 ignored output 中。

## 交接纠错及补充修复

- `eirin-edge-inputs.json` 指向 **72/300 DPI、各 24 个文字层**的合成页；不是 72/300 个图层的实际 Photoshop 实验。300 层测试仅验证脚本生成速度和结构。
- 原接力复核为主线补位，并非独立子代理复核；本次直接重算原始记录和像素，不仅检查已有 PASS 字段。
- worktree 下的引用守卫此前将绝对路径中的 `.worktrees` 视为被排除目录，导致扫描为空。改为相对仓库根检查，保留 output 等实际应排除的目录；新增回归用例，20 项引用检查通过。
- 独立运行 PSD、GUI、pipeline 定向回归：89 项通过。旧 `.pytest_tmp` 权限问题通过任务专属临时目录解决，没有删除共享缓存。
- 原始 gate 的 memory lint 失败是实际失败，不是“全绿”。主 checkout 的记忆维护不在本次修改范围。

## 已有行为修复

保留按需导出必需的 clean 底图；运行时使用独立底图副本，避免误改用户已打开文档；恢复 PS 偏好和活动文档；暂存 PSD 成功后原子发布；超时通过取消标记隔离迟到任务，终止标记到达前保留锁；GUI 使用只读 GET 进度查询，失败后须显式重试。

若 PS 完全不再执行脚本且没有终止标记，当前服务进程会保留隔离锁；恢复此类故障仍需处理 PS 并重启服务。没有自动强杀 Photoshop。
