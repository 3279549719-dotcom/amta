## 考题一（今天推演的核心判断题）

**Q: embedded 和 chained 的区别到底是什么？**

答：不在"什么时候触发"，在**谁强制执行绑定**。
- embedded：CPU 强制。代码路径跑到那一行必然执行（import 即命运），100%。
- chained：清单/协议强制。agent 按编号步骤走到槽位执行，高概率但执行者是 agent。
- standalone：无绑定，赌注意力。
- 同一个条件写在代码里是结构；写在 prompt 里是判断（可能被忘）。

**Q: 为什么 gen_report 挂 CLAUDE.md 第 33 行失败，prompt.md 第 11 步成立？**

答：漂浮规则 vs 编号槽位。agent 逐号走清单必然路过槽位；漂浮规则靠"注意到"。
但注意：prompt.md 第 11 步只管辖 ralph 使命会话，交互会话在辖区外——这就是
"/finish 还要我提醒"的病根：**修好的槽位管不到日常会话**。

**Q: 任务→工具映射表是不是过度设计？**

答：按任务类型加行的表=过度设计，烧掉。只有新增**结构性事件**（产物落盘/收尾/
pre-push，全系统就三四个）才加一行的表=架构。需要安排触发的只是那一小撮
"忘掉也不塌、但你仍然想要"的工具。判别式：**一个工具能不能被忘掉，取决于它
有没有结构性锚点**。03_translate 不会忘（验收塌），gen_report 会忘（表面完成）。
