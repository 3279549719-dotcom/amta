04 / SKILL LAYER

skill 层：2678 token 的账单，与「槽位」到底是什么

这是你说要重点理解的部分。先把机制讲透，再谈砍法和槽位设计。

两层加载：catalog 是房租，正文是按量付费

catalog 层 · 每轮必烧

36 SKILLS × NAME+DESCRIPTION ≈ 2678 TOKEN / 轮
  • 36 个 SKILL.md 的 frontmatter（name + description）在每轮会话开始注入 system context——不管你这次问什么
  • 这就是「注意力税」的实体：房租，住不住都交
  • description 是每个 skill 唯一的广告位：AI 凭它决定要不要往下读
→

正文层 · 按需付费

MATCHED → READ SKILL.MD FULL TEXT
  • 只有当 AI 判断某 skill 与当前任务相关，才 Read 它的全文
  • 没被匹配的 skill 只付过房租，不产生正文成本
  • 「感觉 skill 没被主动用」= 路由槽位不硬，不是机制缺失

槽位设计的本质：把 standalone 往 chained 拉

用三命运判据看 skill 层：所有 skill 天生是 standalone 命运（无绑定、赌 AI 注意力）。「槽位设置好」= 通过三条杠杆把转化率拉高：

杠杆做法判据
去重同职责合并：grill 家族 4 个占 4 个槽 → 留 1 个（grilling，唯一可自动触发的），grill-me / grill-with-docs / to-questionnaire 归档或观测。research vs researcher（后台调研 vs 外部调研子代理）同理二选一两个 skill 的 description 互换后你分不出差别 → 必有一个该走
广告位每条 description 必须答出「什么时机触发 · 谁触发 · 产出什么」。答不出的说明连你自己都不知什么时候用它，AI 更不会read it like a router：description 是路由表的一行，写不清路由就删路由
命中观测砍完明显的，剩下一周不动，用 dsh Trajectory / trace_probe 看真实命中，0 命中的归档（不是删，archive 可回溯）马斯克五步：删除须有 trace 证据，不拍脑袋
SOCRATIC · ④的练习

假设明天开始，catalog 只允许保留 10 个 skill（其余全部归档、随时可装回）——为了「手动翻译会话顺畅清晰透明」这个 Phase 3 目标，你圈哪 10 个？

圈完你会发现：名单里的每个名字你都能说出「它在哪类任务里救过我」；说不出的，命运自动浮出来。这份 10 人名单，就是你 skill 层的路由表初稿。
