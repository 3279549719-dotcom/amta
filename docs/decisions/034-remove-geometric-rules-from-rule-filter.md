# ADR-024：从 rule_filter 移除几何规则（edge_box / extreme_aspect）

- **日期**：2026-09-08
- **状态**：已接受
- **分支**：`exp/remove-geometric-rules` → `main`

## 背景

`rule_filter` 是 OCR 之后、翻译之前的确定性过滤层，原本包含 4 条规则：

1. `pure_punct`：OCR 文本全是标点 → 过滤
2. `pure_number`：OCR 文本全是数字 → 过滤
3. `extreme_aspect`：框宽高比 > 8 → 过滤
4. `edge_box`：框边缘距页面边缘 ≤ 8px → 过滤

引入几何规则（3、4）的初衷是：在 LLM 看到之前，用确定性的形状标准过滤掉假框（噪点、扫描边缘、刻度线等）。

## 问题

全 40 页漫画（东方《单翼停留之地》）审计发现，9 个被 rule_filter 过滤的框中：

- **真杂质 2 个**：p2 刻度线（pure_punct）、p6 页面纯黑竖条（extreme_aspect，OCR 乱码）
- **明确误伤 6 个**：p13 竖排喊叫"うおおお!"、p16 竖排对话（贴边 2px）、p20 横排旁白（贴边 7px）、p22 竖排对话（贴边 5px）、p33 竖排长对话、p41 封底标题
- **边界 1 个**：p31 页面边缘竖线（OCR 有文字但肉眼更像噪点）

**误伤率 6/9 = 67%**。其中：
- `edge_box` 规则 100% 误伤（3/3，零真杂质）
- `extreme_aspect` 规则 60% 误伤（3/5）

## 第一性原理分析

几何规则的底层假设是：
- "极端宽高比 = 假框"
- "贴边 = 假框"

这两个假设在日漫场景下从根上就错了：
- **竖排对话天然高宽比大**：日文漫画大量使用竖排文字，一个正常的竖排对话气泡，宽高比很容易超过 8
- **气泡天然贴边**：漫画气泡经常顶到页面边缘或出血区域，贴边 2-7px 是正常现象

被误伤的 6 个真实对话，检测器（RT-DETR-v2）给出的 confidence 全部 > 0.89，说明检测器本身认为它们是高置信文字框。几何规则反而把检测器的高置信结果误杀了。

## 考虑过的替代方案及否决理由

| 方案 | 否决理由 |
|---|---|
| 提高 detect confidence 阈值到 0.8 | 瓦片化捡回来的框外小字，35% 的 confidence < 0.8（包括"いたい!"0.771、"ご苦労"0.766 等真实小字）。提高阈值会误伤这些小字。 |
| 加"无假名长文本"规则 | 为全 40 页 1-2 个假框预设一条新规则，属于过度工程。且纯汉字标题等边界情况会被误伤。 |
| 提取 hayai OCR 第一个 token 置信度作为通用过滤规则 | 方向正确（自回归模型第一个 token 的置信度能有效区分真实文本和乱码），但为全 40页 1-2 个假框，需要修改第三方 OCR 封装、跑全本调 threshold、维护新规则，性价比太低。记为未来方向，暂不落地。 |
| 引入 VLM 复审被过滤框 | 之前已证明 VLM 判断真假文字不稳定，有时把背景当 drop，有时把假框当真文字瞎编。不可靠。 |
| 翻译 prompt 加"乱码输出空字符串" | 可行且简单，但属于可选优化。全 40 页仅 1-2 个假框流下来，LLM 已能自行识别乱码并输出占位符，影响极小。 |

## 决策

**从 rule_filter 中移除 `edge_box` 和 `extreme_aspect` 两条几何规则，仅保留 `pure_punct` 和 `pure_number` 两条基于 OCR 文本内容的规则。**

理由：
1. 几何规则的底层假设在日漫场景下不成立，误伤率 67%
2. `pure_punct` / `pure_number` 基于 OCR 文本的字符构成，是确定性的、可靠的信号
3. 移除后全 40 页仅 1-2 个假框（p6 黑竖条等）会流下来，LLM 能自行识别乱码，影响极小
4. 符合"最小改动、最大利用已有能力"原则，不引入新的冗余复杂度

## 后果

### 正面
- 救回 6 个被误伤的真实对话（p13/p16/p20/p22/p33/p41）
- rule_filter 逻辑更简单，从 4 条规则减为 2 条
- 不再依赖"竖排=假框""贴边=假框"等错误假设

### 负面
- p6 黑竖条等极少数假框会流到翻译阶段，LLM 输出"（此文本疑似乱码，无法解析）"或类似占位符
- 如未来假框数量增多，可考虑：(a) 翻译 prompt 加"乱码输出空"；(b) 落地 OCR 第一个 token 置信度规则

### 验证
- p6 黑竖条流下来后，LLM 翻译输出"（此文本疑似乱码，无法解析）"，证明 LLM 有能力识别乱码
- 真实文本（r00/r01/r02）的 hayai OCR 第一个 token 置信度全部 > 0.9，p6 乱码第一个 token 置信度仅 0.0249，验证了置信度信号的有效性（暂不落地）
