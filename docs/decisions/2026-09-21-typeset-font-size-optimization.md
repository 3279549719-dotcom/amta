# Typeset 字号优化 — 2026-09-21

## 本次合并

`experiment/no-length-scale` → main。核心改动：

1. **`overflow_tolerance = 0`**（原 2）：竖排列严格不超 `max_chars`。原先允许中间列超 2 字，算法为了少列数宁愿超列，导致最长列变长、`_fits` 高度检查失败，二分被迫降字号。竖排宽度本有余量，应靠多分列而不是超列来排满。
2. **移除 `length_scale` 预压缩**：`typeset_station.py` 原先按译文长度比砍字号（`scale = 1.0 / (1 + length_increase * 0.5)`），`fit_font_size` 本身已经会根据译文长度二分找最大可放字号，外层再砍一刀是双重压缩。现在 `scale = 1.0`，直接用 `src_base_size` 作为上限。
3. **删除死代码**：`LINE_HEIGHT_RATIO = 1.2` 和 `CHAR_WIDTH_RATIO = 1.15` 已被 `_font_metrics()` 的 `font.getmetrics()` / `getlength()` 替代，无调用方。

## 后续待办

### 1. 行高 `getmetrics()` 偏松

现在行高用 `font.getmetrics()`（`ascent + descent`），微软雅黑 sz=15 时 `line_h = 20`（1.33 倍字号）。这个值偏松，压紧（比如 1.15 倍）可能让字号再涨一截。风险是中文标点（！？……）的下行空间可能不够，需要视觉验证。

### 2. 横/竖排方向应按 category 区分

现在 `fit_font_size` 用 0.70 阈值切换横竖排：首选方向字号不小于另一方向 70% 就保持首选。实测删掉 0.70 后，宽扁标题横幅被切成竖排，列顺序/字序对不上，文字读不通——证明 0.70 在保护横排框。

更好的做法是按 `category` 分：
- 对话框 → 强制竖排（和原书一致）
- 标题/封面/后记/日期 → 保持横排
- 不要用长宽比阈值一刀切

canon 里已经有 `category` 字段，改动量小。
