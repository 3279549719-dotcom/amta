① 管线数据流 — 方向信号全程缺失

P0 致命 ③ p14 翻译错位 — 文字放错气泡

现象

r01 原文「ちょっと待て! 仮行さぼりたいだけでしょ」被拆成「等一下！」+「只是想偷懒不修行吧」两条，r02 同样被拆，导致 r01–r11 全部偏移，r10/r11 原文译文丢失。

根源（代码级）

parse_translation_array() 只校验输出数量=输入数量。LLM 拆前2条+丢后2条，总数仍相等，校验通过。mechanical_guardrails 只查 id 存在性，不查语义对应。翻译数据生成于修复前(11:35)，typeset 重跑用了旧数据。

修复：重跑翻译阶段 → 增强 guardrails（译文/原文字符长度比异常检测 + 术语命中校验）
P1 严重 ① 横竖方向不一致 — 原文横排变竖排 / 竖排变横排

现象

p11 r04：原文横排「そんなことより研究研究」(bbox 380×222) → 译文竖排5列
p13 r02：原文竖排「お、落ち着け…」(bbox 166×691) → 译文横排9行每行2字「伪竖排」
p11 全部7区域：无一例外全选 vertical

根源（代码级）

fit_font_size() 第104行 if v_size >= h_size 纯比字号。短文本触达 MAX_SIZE=52 天花板时横竖平局 → 默认竖排。窄长框长文本竖排需多列超宽 → 横排字号反而更大 → 选横排。管线全程无方向信号。

修复：bbox 长宽比推断 preferred_direction（高宽比>1.5→竖排，宽高比>1.5→横排）→ fit_font_size 优先在首选方向最大化，仅当首选字号<次选70%才切换 → 平局时按首选方向
P2 中等 ② 竖排标点横置 — 「……」「——」不旋转

现象

竖排文本中的省略号「……」是水平排列的六个点，在竖排文字流中突兀。p11 r01/r03 均有此问题。竖排折行也无避头尾处理。

根源（代码级）

typeset_render.py 竖排分支逐字 draw.text()，所有字符原样绘制无旋转。wrap_vertical() 简单切片无避头尾。

修复：竖排渲染时对 ……——～ 等字符旋转90°绘制 → 竖排折行增加避头尾规则
