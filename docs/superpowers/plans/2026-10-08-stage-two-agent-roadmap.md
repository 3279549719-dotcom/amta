# Stage Two 实验与 Agent 改进路线图

**性质：** 这是一份决定下一步做什么的路线图，不是批准执行的 Specification 或代码实施方案。目标是用真实任务观察 Agent，再针对反复出现的问题做最小改进。

## 先区分两条线

| 工作线 | 要回答的问题 | 直接产出 |
|---|---|---|
| Stage Two 任务实验 | Agent 能否把一个真实需求从讨论做到可靠交付？ | 可供你审阅的实际成果和完整轨迹 |
| Agent 改进 | 它为何偏离任务？下一次怎样少犯同一类错误？ | 对现有提示、Skill 或工具的一项有证据的小修正 |

两条线可以交替进行，但每次要知道当前在验收哪一个目标。翻译任务中遇到 Agent 问题，先记录证据；除非当前任务无法继续，不临时把任务扩大为改造整个 Agent。

## P0：继续做几次 Stage Two 真实任务

每次只选一个边界明确的任务，尽量使用现有 Pipeline 和工具。按以下顺序走：

1. **粗计划。** 你给出想要的结果和一两个真实样本；Agent 先调查现状，说明准备怎么做、有哪些选择及风险。此时不改生产流程。
2. **讨论。** 你决定目标、范围、效果标准及可接受的取舍。Agent 根据讨论修正方向。
3. **详细 Specification。** Agent 写清楚要交付什么、哪些情况算成功、哪些情况需要你判断。你确认后，它再写可执行的实施方案。
4. **执行并做基本验证。** Agent 按已确认的范围实现，同时做必要的定向检查，拿一个真实样本跑出可看的结果。不能把所有检查推迟到你审阅之后。
5. **你看实际结果。** 这一步是效果与方向检查。若不合意，回到讨论或调整 Specification；若合意，Agent 继续做更多样本和边缘情况验证。
6. **最终验收与收尾。** Agent 交付结果、测试证据和剩余问题；你确认最终成果。收尾流程按项目现有规则处理。

第 5 步的“看过觉得 OK”是允许继续扩大验证的判断；第 6 步才是最终验收。这样你不必在看不到实际成果时批准大规模测试，也不会收到完全没做基本检查的半成品。

**实验选题：** 先选两到三个彼此不同、但规模可控的真实需求。每次只固定输入、预期结果和允许改动的范围；不为了“测 Agent”额外发明一套流程。实验完成后保留完整 session 轨迹，记录总耗时、是否调用了该用的 Skill、是否跑了无关全量任务、是否在原失败路径上验证成功。

## P1：用实验结果改 Agent，每次只改一个主要原因

每次实验结束，把偏差分成四类：任务说得不清楚、现有 Skill 没被调用或没约束住行为、现有工具给了误导性结果、DSH 运行环境故障。先依据轨迹找到最早的错误决策，再选择最小改法：

1. 若只缺一句任务边界，改下一次任务的提示或 Specification 模板。
2. 若同类错误重复出现，先修已有 Skill 的触发条件或操作顺序，并用下一次任务验证是否真的生效。
3. 若工具会把失败说成成功，另开一个小型工具修复任务；这类问题可以优先处理，因为它会污染所有后续实验的判断。
4. 若问题属于 DSH 沙箱或电脑环境，记录真实复现路径并交给对应项目处理，不让翻译 Agent 用全仓扫描代替定位。

**判断改进是否有效：** 下一次相似任务中，它是否更早使用正确的 Skill、是否只检查相关路径、是否在原操作上得到红到绿的证据、是否避免重复全量运行、是否如实报告未完成事项。看行为和结果，不以“写了新文档”为成功。

## P2：有证据后再考虑结构调整

MCP、chain、embedded 模式、新的自动门禁或新 Skill，暂时都不是默认动作。只有连续几次实验都显示同一个限制，而且现有提示、Skill 和工具的小改动解决不了时，才单独写 Agent 改造 Specification，比较收益、复杂度和迁移代价，再由你决定是否实施。

## 本轮已知事项如何放进路线图

- `finish` 递归错误和单页 `typeset` 重跑已经有修复或成功证据，不作为新的 Stage Two 实验任务重做。
- 上次 session 显示：新 `diagnosing-bugs` Skill 没有在首次故障时自动发挥作用；后来使用时，排查范围又扩大到全仓。下一次实验重点观察调用时机与范围，再决定是否只改现有 Skill 的一两条指令。
- `fastcheck` 对失败输出的判断和 gate 文案有潜在误导风险。单独用定向复现确认后，小范围修复；不把它与 Stage Two 产品任务绑成一个大改造。
- DSH 沙箱标签、历史 pytest 临时目录、未跟踪探针和 `.acl-recovery/` 的处置仍留在 `docs/friction.md`，不阻塞这个路线图，也不擅自清理。
