# 竖排列尾逗号修复 — High Effort 边缘案例验证

## 任务目标
对已实现的 `column_end_pause_mask` 列尾逗号消冗功能做严格的边缘案例验证，
确保在所有渲染路径、所有背景类型、所有字体条件下都正确，且不引入回归。
然后解决与 main 分支的合并冲突，使代码可以干净合并。

## 背景
上一轮（low/medium effort）已实现核心功能并通过基础验证：
- `vertical_punct.py` 新增 `column_end_pause_mask()` 纯函数
- `typeset_render.py` 竖排渲染路径集成掩码（只跳过绘制，字格照常推进）
- `vlm_render.py` 同步集成
- 17 条单元测试，6 页 before/after 对比图，606 tests passed

但以下边缘案例尚未严格验证，且 main 分支已重构 `_render_vertical`，合并会有冲突。

## 验证项（必须全部通过）

### 1. 白字深底气泡
- 问题：之前验证脚本曾误判 page_8 r11（白字深底），因为背景不是纯白
- 要求：
  - 找出 work 中所有白字深底气泡（文字颜色接近白色，背景深色）
  - 对这些气泡重新渲染，确认列尾逗号被正确消隐
  - 确认消隐后深色背景上没有残留的逗号墨迹像素
  - 确认文字位置零位移（与无掩码时逐像素对比，除被掩码字格外无差异）

### 2. VLM 渲染路径
- 问题：`vlm_render.py` 有独立的竖排渲染逻辑，之前只做了基本集成
- 要求：
  - 找到使用 VLM 路径的页面（ocr_engine == "vlm-paratext"）
  - 对这些页面重新渲染，确认列尾逗号被消隐
  - 确认 VLM 路径的字体、字号、颜色处理不受掩码影响
  - 如果 VLM 路径有独立的断列逻辑，确认掩码在正确的时机应用

### 3. 横排零影响
- 问题：掩码只应在竖排路径应用，横排路径必须完全不受影响
- 要求：
  - 写一个 spy/mock 测试：横排渲染时 `column_end_pause_mask` 不应被调用
  - 找到 work 中所有横排气泡，重新渲染，确认输出与修复前逐像素一致
  - 确认横排文本中的逗号（句中、句末）全部正常显示

### 4. 边缘案例单元测试
- 要求新增以下测试用例：
  - 单列文本（只有一列，列末逗号不应消隐，因为没有下一列承接断句）
  - 单字符列（列只有一个逗号，不应消隐，避免整列空白）
  - 连续逗号（"文字，，" 第二逗号在列末时的处理）
  - 半角逗号 "," 和全角逗号 "，" 都应被掩码
  - 顿号 "、" 在列末应被消隐（同族）
  - 句号 "。"、感叹号 "！"、问号 "？" 在列末不应被消隐（强终止符）
  - 省略号 "…" 在列末不应被消隐
  - 分号 "；"、冒号 "：" 在列末的处理（当前实现保留，确认这是正确的）

### 5. 合并冲突解决
- 问题：main 分支把 `_count_vertical_lines` 重构成了 `iter_vertical_rows`，
  重写了同一个 `_render_vertical` 循环，且主循环是按行迭代而掩码是按字符下标
- 要求：
  - 从 main 分支合并到当前分支，解决所有冲突
  - 确保掩码逻辑在重构后的循环中正确应用（按字符下标定位，不是按行）
  - 合并后全部测试通过
  - 合并后重新生成第4页对比图，确认功能正常

### 6. 全量回归
- 要求：
  - `uv run python -m pytest tests/ -q` 全部通过（除既存失败外无新增失败）
  - `npm run check` 通过（如果适用）
