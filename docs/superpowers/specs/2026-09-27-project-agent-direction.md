# AMTA 项目 Agent：建议形态与现有基础

状态：设计建议；本次修复不实现自主运行器。2026-09-27。

## 推荐形态

一个后台主控 Agent，复用现有 Python 管线和工具。GUI 是任务提交和查看证据的入口；
Agent 的运行寿命不依赖聊天窗口。LLM 负责选择下一步，工具负责执行，持久状态负责恢复。
第一版不需要多个常驻 Agent，也不需要替换管线。

同一主控有两种任务范围：

- 翻译任务：原图进，PNG 与按需 PSD 出；排查失败、生成报告、定向重跑，直到验收或升级。
- 改进任务：从失败样本复现问题，在隔离代码版本上提出和测试修改；通过固定回归样本与视觉
  对照后再采用。不能在交付任务运行中直接改它使用的管线，也不能修改验收标准使自己过关。

## 需要补齐的运行层

每次启动/恢复任务按固定入口加载：项目身份 → 当前目标与完成条件 → 上次状态与证据 →
可用工具清单 → 相关记忆摘要。技能按需要读取，不把所有历史和技能全文塞进每轮。

任务状态至少保存：目标、输入页、期望输出、当前步骤、尝试记录、产物引用、代码/模型/配置
版本、剩余预算、等待人工的具体原因。状态由运行器落盘，不能只存在模型上下文里。

状态流：queued → running → verifying → done；验证失败可回到 running；
需要人时进入 waiting_for_human；耗尽预算或无法恢复时保留失败状态和证据。
waiting_for_human 收到答案后从断点继续，服务重启后也能恢复未完成任务。

运行循环：读取状态 → 选择一个行动 → 调用工具 → 保存结果 → 检查完成条件 → 继续。
没有下一条聊天消息也应由运行器启动下一轮；启动身份文件、skill 或 hook 不能代替这一机制。

## 验收和自主边界

执行成功、结构完整、视觉/语义质量是三种不同证据。数字相等或文件存在不能替代画面验收。
项目已有的质量红榜和报告可作为观察入口；未知、未测和失败必须保留，不能被空结果吞掉。

缓存修复、契约统一、可逆错误修复和定向重跑应自行完成，不逐项问用户。
翻译歧义存在实质取舍、画面损伤无法恢复、超过已授权成本、扩大任务范围或不可逆发布时，
携带证据提出具体问题。无新证据的重复尝试应停止换路线或升级，不无限循环。

最小落地顺序：先做一个可恢复的翻译任务闭环，再接入隔离的管线改进任务。
实现时复用现有工具，不新增与 artifact、report、memory 职责重叠的另一套系统。
