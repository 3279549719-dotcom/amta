# 短促发声空译文修复设计

## 目标

收窄普通漫画翻译的空译文政策：可识别、可发音且承担人物表达或叙事作用的短促人声必须翻译；只有纯标点与确实不可识别的 OCR 乱码可以输出空字符串。修复不得依赖页码、region id 或具体日文词条，并继续保留“空译文不进入 inpaint/typeset”的安全契约。

本轮以 p64 为唯一开发样本。只有候选方案通过 p64 的文本、页面和非退化验收后，才首次运行 p52 与 p43 的同类条目作为隐藏验证。

## 根因与边界

`src/amta/translation/translate.py` 的系统提示把“拟声词”整体列入无需翻译的内容。解析器允许合法空字符串，`stage3_minimal` 原样保存结果，下游再按非空译文筛选 inpaint/typeset 区域。因此现有组件都遵守各自契约，错误来自提示词把两个不同概念合并：

- 应保留为空：没有语言内容的纯标点，以及模型确实无法识别的 OCR 噪声；
- 应翻译：呻吟、喊叫、笑声、叹息、哼声、感叹词，以及在画面中承担动作或情绪表达的拟声。

本轮不建立“所有非空 OCR 都必须得到非空译文”的机械不变量。该不变量会破坏既有乱码防线，也无法从字符串存在与否推断语义是否可识别。

## 方案选择

### 第一候选：只收窄提示词

修改 `_SYSTEM_PROMPT` 的语义边界，明确要求翻译有叙事作用的短促发声，并把允许为空的范围限定为纯标点与确实不可识别的乱码。翻译仍保持一页一次调用、零重试、数组位置绑定及现有 artifact schema。

这是首选方案，因为根因就在提示词，且无需增加分类器、网络调用或新的失败状态。提示词描述类别而不枚举具体词条；中文措辞由模型结合本页对白上下文、人物语气和作品知识生成。对女性角色的声音表现通过“保留人物语气、情绪和强弱”这一通用要求实现，不建立性别或角色专用分支。

### 受控升级：一次语义补救

仅当第一候选在 p64 上仍返回空译文时，才进入第二轮设计：对“来源可识别但首轮结果为空”的条目做至多一次小批补救，并记录额外调用。补救仍不得把纯标点或乱码强制翻译。

这不是首轮实现内容。若需要启用，必须先找到不依赖具体页码或词条、且能保留乱码防线的候选判据，再按新的 RED-GREEN 循环实现。

### 否决方案：确定性词典

不为 p64、p52 或 p43 的文本建立映射表。词典只能让已知样本变绿，不能证明系统学会区分“有叙事意义的人声”和“不可识别输入”。

## 数据流与不变量

生产数据流保持不变：

1. canon 中的页面文本作为 JSON 数组进入 `translate_plain`；
2. 系统提示定义语义取舍，用户提示继续定义数组格式和漫画口语风格；
3. 模型返回同长度 `translations` 数组，解析器按位置绑定 region id；
4. 空字符串继续是合法值，translation artifact schema 不变；
5. inpaint 和 typeset 继续只处理非空译文。

首轮不修改 `stage3_minimal.py`、翻译适配器、guardrail 接口、artifact schema 或下游过滤逻辑。若测试发现这些既有契约与当前源码不一致，先记录为证据，不把无关重构夹入本轮。

## 测试设计

先写失败测试，再修改提示词。

- 通用短促人声测试：通过捕获 mock LLM 收到的 system message，证明政策明确要求翻译可识别的人声、感叹和有叙事作用的拟声，并且不再把所有拟声词归为空译文。
- 合法空译文测试：mock LLM 对纯标点和不可识别乱码返回空字符串，证明 `translate_plain` 仍接受这些结果且保持数组位置。
- 下游保护回归：使用已有 inpaint 契约测试或补充最小测试，证明空译文对应的框不会进入擦除计划；不改变该行为。
- 格式契约回归：现有同长度数组、解析失败整批为空、region id 绑定和翻译工位测试继续通过。

Mock 测试验证代码与提示词契约，不冒充真实模型效果。真实模型的通用性由预注册页面顺序验证。

## 实验与验收门

### 开发门：p64

用受支持的 pipeline 入口只重跑 p64 的 translate 及其后续依赖阶段，并记录翻译调用次数和各阶段耗时。候选必须同时满足：

- r08 得到符合人物情绪和上下文的自然中文短促发声；
- 原日文被 inpaint 清除，中文排版可读；
- 其余八条译文没有明显语义退化；
- 仍是一页一次翻译调用，除非第一候选被证伪并正式进入受控升级。

若失败，最多再进行两轮单一假设实验。每轮先写明假设，只改变一个变量；第三轮仍失败则停止并重新讨论架构，不叠加补丁。

### 隐藏验证门：p52 与 p43

仅在 p64 通过后，首次重跑 p52 与 p43。验收只针对已检测到的同类短促发声：两者都应得到自然的中文表达并进入后续渲染。任一失败即说明方案不够通用；不得为三页逐条增加规则。

p43 的透明气泡漏检、p52 的其他排版问题、p62 inpaint、p44 双关、p41 OCR 乱码和 p42 字号均不属于本轮修复。

## 视觉与回归验证

通过 `artifact.py` 定位产物，通过 `gen_report.py` 生成统一报告，并比较修改前后的 translation、clean、final 和页面 ledger。视觉检查关注原文是否清除、短促译文是否可读及其他对白是否退化；不以单一像素指标代替肉眼判断。

代码验证依次包含相关 translate、guardrail、inpaint/pipeline 测试，随后运行完整 `uv run python -m pytest -q` 和仓库规定的收尾门。任何完成声明都必须引用本轮新鲜命令输出及生成的 artifact。

## Loop Engineering 产出

本轮优先复用现有 prompt、mock seam、pipeline、artifact、报告与测试能力。只有实际探索暴露出可重复且能用命令判真的工作流摩擦，并且该摩擦真实阻断过实验，才在 `docs/friction.md` 记账并考虑新增工具或 Skill。不会为了展示 self-refinement 预防性制造一层编排。

若闭环成功，可复用知识应落在决策记录、回归测试和必要的 lesson 中：它们共同把“过去合理但边界过宽的规则如何被证据收窄”变成下一次 Agent 可检索、可执行、可验证的能力。

## 非目标

- 不修改 p62 或合并 `fix/text-ink-mask`；
- 不修 p43 detection；
- 不重新处理 p59；
- 不实现通用 OCR 垃圾分类器；
- 不增加页码、region id、具体日文、性别或角色硬编码；
- 不无限重试，不改变 translation artifact schema；
- 不破坏空译文保护原文的下游契约。
